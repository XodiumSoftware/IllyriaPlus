## Content Conventions

### Page Structure

All documentation pages must follow this format:

1. **H1 Title** — Page name (matches filename in kebab-case)
2. **One-line summary** — Single sentence description
3. **Property table** — Optional two-column table for structured metadata
4. **Effect** — What the feature/item does
5. **Notes** — Additional details, tips, or warnings
6. **Related links** — Cross-references to other pages

### Property Tables

Use two-column tables for structured data:

```markdown
| Property   | Value                            |
| ---------- | -------------------------------- |
| Applies To | Pickaxes                         |
| Max Level  | 3                                |
| Source     | Enchanting table, anvil, trading |
```

### Image References

- Use the `mc-icon` CSS class for Minecraft texture icons:
  ```html
  <img class="mc-icon" alt="" src="../img/item/diamond.png"> Diamond
  ```
- Paths are relative to the page location (`../img/...` from section pages)
- Always include `alt=""` for decorative icons (accessibility)

### Cross-References

Link to other pages using relative paths:

```markdown
[Tether](tether.md)              <!-- Same section -->
[Weapons](../weapons/index.md)   <!-- Different section -->
```

### Naming Conventions

- **Files:** `kebab-case.md` (e.g., `elytra-trims.md`, `spawn-protection.md`)
- **Sections:** Lowercase, single word when possible (e.g., `gameplay/`, `qol/`)
- **Images:** `snake_case.png` matching the block/item name

## Content Workflow

### Adding a New Page

1. Use the `wiki-add-page` skill or manually create the file in `src/<section>/`
2. Register the page in `src/SUMMARY.md` under the appropriate heading
3. Follow the page structure conventions above
4. Add any required images to `src/img/<category>/`
5. Run linting: `npx markdownlint-cli2 --config .markdownlint.json "src/**/*.md"`
6. Build locally: `mdbook build`
7. Commit and push

### Updating After Plugin Changes

When IllyriaPlus code changes (enchantments, mechanics, recipes):

1. Use the `wiki-sync` skill to audit differences
2. Create new pages for new features
3. Update existing pages for behavior changes
4. Remove pages for deleted features (and fix inbound links)
5. Update `introduction.md` if the feature category changed significantly

### Adding Images

1. Locate the texture in `../IllyriaPlus/IllyriaResourcePack/assets/minecraft/textures/`
2. Copy to `src/img/<category>/` (strip suffixes like `_front`/`_side`)
3. Reference in pages using the `mc-icon` class (see Image References above)

**Important:** When documenting features, always verify against the actual IllyriaPlus source code, not assumptions. The plugin uses compile-time constants, so check the `private const val` values in mechanic/enchantment objects.

### Full Validation

```bash
# Lint all Markdown
npx markdownlint-cli2 --config .markdownlint.json "src/**/*.md"

# Build and check for broken links
mdbook build

# Verify no missing images referenced in pages
find src -name "*.md" -exec grep -l "\.png\|\.gif\|\.webp" {} \; | while read f; do
  dir=$(dirname "$f")
  grep -oP '(?<=src=")[^"]+' "$f" | while read img; do
    [ ! -f "$dir/$img" ] && [ ! -f "$img" ] && echo "Missing: $f -> $img"
  done
done
```

## Notes for Agents

- **No automated tests** — Validate by building (`mdbook build`) and linting (markdownlint)
- **Source of truth** — The IllyriaPlus codebase is authoritative for feature behavior; wiki content must match the code
- **Images** — All Minecraft textures come from the IllyriaResourcePack; do not use external sources unless necessary
- **Tables** — Keep property tables narrow (max 2 columns: Property/Value); wide tables break mobile display
- **Links** — Always use relative paths for internal links; absolute URLs only for external references
- **SUMMARY.md** — Must be updated whenever adding/removing pages; it's the mdBook navigation source

## Claude Code Workflow

- Number tasks in the name (e.g., "1. Add Verdance enchantment page", "2. Update Tether documentation")
- This makes it easy to reference specific tasks in conversation

**After completing each task:**
- Ask the user if they want to git commit the changes or adjust before committing

**After making edits:**
- Always update `SUMMARY.md` if adding/removing pages
- Verify the build passes with `mdbook build`
- Ensure markdownlint passes with 0 issues
